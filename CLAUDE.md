# Roster Grader

An app built on app_builder. The platform rules live in `platform/SPEC.md`: read its "For Claude Code" part before changing anything outside `src/` or `test/`. This file holds only what's specific to this app.

## Decisions already made (do not relitigate without asking)

- **Mode:** solo. Targets are set in `app.config.json`.
- **Logic is pure and deterministic:** no clock, no `Math.random()`, no I/O in `src/app.ts`. Randomness comes from the seed.
- **Everything tunable is config:** rules live in typed config objects with documented defaults. No magic numbers in logic.

## Rules

- Run `npm run typecheck && npm test && npm run build` before every commit. If the Play target is on, also `npm run build:play` (it fails on any network code).
- Never edit `platform/`. A platform change goes into app_builder, then `sync` brings it here in its own commit.
- No new dependencies without asking.
- The client loads nothing from other origins and uses no inline scripts or styles: the host's CSP is `'self'` only.
- Text from players goes into the page as text (`el(…, { text })`), never as HTML.

## Working rules for agents (shared across J's repos)

- **Public-safe by default.** Write everything as if this repo will be public tomorrow. No secrets or real personal data in code, config or history (keys go in env vars and GitHub secrets). No security through hidden code: anything that would be unsafe if the repo went public is a bug, so flag it.
- **PRs, never pushes to `main`.** Every change goes through a pull request that J reviews and merges. Never merge on J's behalf.
- **Every PR opens with a risk tier and a 60-second check.** First line: `Risk: low | medium | high`. Then what could break and the exact lines worth reading.
- **High risk = these paths, or anything that publishes or touches auth:** `.github/`, secrets and tokens, auth and host code, `wrangler.toml` or other deploy config, anything that makes something public. High-risk PRs get an independent review (a fresh agent that hasn't seen the work) before J is asked to merge.
- **No generated files in PRs.** Outputs that a workflow rebuilds stay out of PRs, so they can't collide with that workflow.
- **Small PRs.** One purpose each. Split anything J can't check from a phone in about a minute.
- **Check before explaining.** Read the log, run the test, open the file. A guess is labeled as a guess.
- **Include a ready-to-paste Claude Code prompt** in each PR, as the alternative to merging.

## App-specific notes

- **What it is:** a read-only page. `src/app.ts` is a stub GameModule (the friends Worker needs one); the model is `src/model/` (pure, no clock, no I/O), the refresh pipeline is `pipeline/`, the page is `src/client/main.ts`.
- **Every weight, threshold and label is in `src/model/config.ts`.** No numbers in logic files.
- **Data:** `data/` (the last good copy of each nflverse source plus `data/roster_grader.json`) and `web/roster_grader.html` are written ONLY by `.github/workflows/refresh-data.yml`. Never include them in a PR. Locally, `npm run refresh` writes them; leave them uncommitted.
- **Builds without data** (CI, fresh clone) use `test/fixtures/sample-output.json` and show a "sample data" banner. After changing the model or the fixtures, run `npm run sample` (a test checks it is current).
- **The page makes no network calls.** Everything is baked in at build time; `pipeline/build-web.ts` fails on network code.
- **Ratings slot:** `RATINGS_SOURCE` in config is off. Turn it on only for ratings we may republish; the refresh refuses otherwise.
- **High risk here:** `.github/workflows/refresh-data.yml` (it pushes to `main`) and anything that changes what the public page shows.
